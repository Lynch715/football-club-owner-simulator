# 《足球俱乐部老板》可玩性优化 · 设计方案

> 日期:2026-07-25
> 对象:`足球俱乐部老板.html`
> 目标:提升可玩性(参与感 / 变化 / 目标清晰),不重做核心、不碰开局难度曲线。

## 一、背景与问题

玩家(游戏设计者本人)诊断本作"可玩性不高",经确认具体指三点(**未**包含"太难"):

1. **太单调、重复** —— 每月操作雷同,决策缺变化。
2. **玩家没参与感** —— 比赛自动踢、结果靠运气,老板决策与场上结果的因果不明显,像旁观。
3. **目标 / 反馈不清** —— 不知往哪使劲,三年在冲什么、好结局怎么来都不明确。

根因:**"没参与感"是病根,另两个是症状。** 因为老板不排首发、比赛自动踢,买完人只能"看";既然场上结果和"这个月干了啥"看不出因果,操作自然显得重复,目标自然不清。

叠加 `游戏审计报告.md` 已暴露的相关硬伤:

- `simulateCup` 的对手是 `pick(随机)`,不看实力 → 弱队可能连过四轮白捡杯冠。
- `finalEnding` 的"奖杯陈列室"只看 `track.trophies>=2`(含杯冠) → "什么都不经营、靠两杯冠进好结局"成立,评价体系重杯赛轻联赛。
- 三档开局难度悬殊却不标注(此项本方案通过"三年蓝图看板"顺带缓解,不改数值)。

## 二、设计方向(已与玩家逐项确认)

- **保留 DNA**:老板不排首发、比赛自动踢。**不**转经理。
- **加一层"赛前会议"**:每场赛前给老板级高层选择,**看得见地改变 xG 赔率**。
- **约束模型**:免费"基调"打底(对称取舍)+ 花资源"加码"(自限)。
- **范围**:两块都做 —— 赛前会议 + 目标/结局清晰化(含堵杯赛漏洞)。
- **平衡红线**:玩家没抱怨难度,**不动开局破产"死亡时钟"**;杯赛修复是"抬高好结局门槛",与玩家在范围题上的选择一致。

## 四、第一块:赛前会议

### 4.1 触发与流程

每有正式比赛(联赛/杯赛),在结算前弹"赛前部署"卡。每月通常 1~2 场。

**工程改动(全案唯一的结构调整点):** `doEndMonth` 现在"先全模拟完、再逐场弹窗"。改成三段,用现有 modal 队列(`queueAll / flushQueue`)串起来:

```
[部署阶段] 对本月每场我方比赛弹一张赛前卡,收集 plan → 存到 fixture(f.plan)/ 杯赛(s.cup.pendingPlan)
      ↓ 玩家全部选完后
[模拟+结算] settleFinance → simulateLeagueMonth / simulateCup(读取 plan)
      ↓
[展示] 逐场 showMatchCentre(含"赛前部署"因果格)→ showMonthReport → 事件/预警/赛季复盘
```

- `simulateMyMatch` 增加可选参数 `plan`;`simulateLeagueMonth` 从 `f.plan` 取,`simulateCup` 从 `s.cup.pendingPlan` 取。
- 若某场没弹到部署(理论上不会),`plan` 缺省=常规,行为与现状完全一致(向后兼容)。

### 4.2 基调(免费,三选一,按 `preview.edge` + 主客 + 赛事重要度动态生成)

基调对 `myXgRaw / oppXgRaw` 施加乘数,菜单**随战况变化**——这是"破单调"的核心。

| 战况(判定) | 选项 A | 选项 B(常规) | 选项 C |
|---|---|---|---|
| 占优 `edge≥2` 或打弱旅 | **全力抢攻** 我×1.18 敌×1.10,`injuryChance+0.02` | 不变 | **轮换保人** 我×0.88;主力 form/morale 保留、`injuryChance-0.02`、年轻替补**整体**多获出场(广度轮换,区别于下方"强推青训"的**指定单人**高风险加码) |
| 下风 `edge≤-2` 或客场遇强 | **铁桶偷分** 我×0.82 敌×0.72 | 不变 | **对攻豪赌** 我×1.20 敌×1.20 |
| 均势 `-2<edge<2` | **压上抢攻** 我×1.10 敌×1.06 | 不变 | **稳守** 我×0.92 敌×0.88 |

- 判定"赛事重要度"用于文案与后续加码强度:保级战(排名靠后)、争冠战(排名靠前且对手榜首附近)、杯赛淘汰赛 → 标注"必须赢/输不起",让选择更有戏。
- 乘数为初值,集中在"可调参数汇总"表,便于压测后微调。

### 4.3 加码(可选,叠在基调上,各自带刹车)

| 加码 | 成本 | 效果 | 刹车(反无脑刷) |
|---|---|---|---|
| **发赢球奖** | 现金 `round(payroll×0.2)` | 本场等效 我×1.08(全队 morale 临时+) | `flags.winBonusStreak` 计数:连发抬高胃口,某场**不发**则 `dressing+`、主力 morale- |
| **强推青训妖人首发** | `coach.authority-15`(需 ≥45) | 指定 1 名 youth/年轻 roster 进首发;赢或平 → 该新星 ability/form 成长加速 + `fans+` + `track.youthPromoted` 计入;输 → `authority-5` 再罚、`dressing+` | 权威慢回复,一年仅够几次 |
| **发布会定调** | 不花钱 | 力挺:赛前 `fans+ / morale+`;施压:看 `coach.discipline`,小概率 我×1.06 | 力挺后若**输球** → `board- & fans 风险+`(加倍还);施压失败 → `dressing+` |

### 4.4 反馈(治"反馈不清 · 单场")

复用 `showMatchCentre` 的"为什么是这个结果"面板,在 `explanation.causes` 里**新增一格「赛前部署」**:

> **赛前部署** · 基调 铁桶阵 → 预期 1.6→1.3;赢球奖 +0.1
> 你用一分钟的保守,换回一个客场平局。

即每场都能看到:我这一手,把预期从 X 挪到 Y,最终拿到 Z。

### 4.5 数据模型改动(第一块)

- `s.schedule` 的 fixture 增加可选 `plan`;`s.cup.pendingPlan`。
- `s.flags.winBonusStreak`(数字)。
- `plan` 结构:`{tone:"全力抢攻"|..., bonus:bool, youthPush:playerId|null, presser:"力挺"|"施压"|null}`。
- `SAVE_VERSION` +1(存档结构变化);旧档按版本校验自动作废(现有机制)。

## 五、第二块:目标与结局清晰化

### 5.1 三年蓝图看板(治"目标不清")

主界面(overview)常驻一张卡,把三年目标铺开——数据全来自 `seasonTargets`,只是显式画出来:

- 三列 = S1 / S2 / S3;每列 = 董事会排名线 / 杯赛线 / 球迷胜场线。
- 当前赛季高亮;已过赛季按 `history` 打 ✓/✗。
- 一句话进度:"距本季董事会目标还差 X 名 / Y 胜"(用 `leagueRank`、`seasonWins` 与 `targets` 现算)。
- 顺带缓解"三档难度不标注":看板一眼看出 `fallen`/`promoted` 前期目标更苛刻。

### 5.2 结局路线卡(治"目标不清" + 提升重玩)

开局"收购完成"屏 + 主界面各放一张"你可以这样被记住",把 5 条好结局路线**开局摊牌**,各自写清条件:

| 路线 | 达成条件(与 `finalEnding` 对齐) |
|---|---|
| 联赛王朝 | 3 年内 2 座联赛冠军 |
| 三冠奖杯室 | 杯赛夺冠 **且 联赛 ≤3**(不再是纯 2 杯) |
| 青训之城 | 提拔青训 ≥7 且 青训等级 ≥4 |
| 经营模范 | 转会净盈利 >1500 且 现金 >5000 且 联赛 ≤6 |
| 稳定强队 | 联赛 ≤4 |

让玩家开局就挑一条冲,不同开局天然适配不同路线。

### 5.3 堵杯赛漏洞(接审计)

- **`simulateCup` 对手按阶段升级实力**:不再 `pick(随机)`。按 `s.cup.stage` 从强度分档抽签——十六强抽中下游、决赛抽顶级——弱队连过四轮概率大幅下降。点球胜率公式沿用(已含实力差)。
- **好结局统一加联赛门槛**:改 `finalEnding`,"奖杯陈列室/三冠奖杯室"要求 `rank≤3`;整体好结局要求联赛不低于设定线,堵住"垫底+两杯冠=好结局"。

### 5.4 数据模型改动(第二块)

- 主要是 UI 与 `finalEnding` / `simulateCup` 的判定逻辑,**新增状态极少**(路线卡为纯展示;看板用现有字段现算)。

## 六、平衡守则与验证

- **不动死亡时钟**:固定月支出、债务利息、破产阈值一律不改。
- **基调对称**:稳守压己方、对攻也喂对方,长期期望接近中性;收益来自"看战况做对选择",正是我们要奖励的参与。
- **加码自限**:赢球奖抬胃口、青训吃稀缺权威、发布会输了加倍还——有钱也不能场场刷。
- **杯赛修复是抬门槛**:方向为收紧上限(好结局要挣),与玩家范围选择一致。
- **验证**:沿用 `游戏审计报告.md` 那套机器人压测(随机流/保守流/放置流,单局数千步),改动后重跑,确认:(a) 放置流死亡月不比现状更早;(b) 好结局不再能靠"纯放置+全选第一项"白捡;(c) 无软锁/NaN/存档读坏。

## 七、范围外(本次不做)

- 不加"亲自排首发/选阵型"(那是转经理)。
- 不改开局三档的数值强度(只做"看板标注"层面的可读性)。
- 不重构渲染层;沿用现有 modal 队列、`renderOverview` 等。
- 旁注:`youthVisit()` 内疑似把 `S` 误写成 `s`(`s.academyLevel`),属既有潜在 bug,**与本方案无关**,如需修复另开任务。
