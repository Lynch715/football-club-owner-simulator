# 《足球俱乐部老板》· 戏剧层设计说明

> 日期：2026-08-14
> 对象：`足球俱乐部老板.html`（单文件，全部逻辑在唯一 `<script>` 内）
> 目标：在已有的「赛前会议 + 三年蓝图 + 结局路线」之上，解决三个仍然存在的乏味点——37 个一次性事件没有前后文、对手只是一个数字、赛季末没有高潮。

## 一、加了什么

四个系统，共用一层新代码（文件内标记为「戏剧层」），全部挂在既有的月度循环和弹窗队列上，没有改动核心的比赛模拟与开局破产曲线。

### 1. 更衣室生态

每名球员在生成时获得一个性格 `persona`（更衣室领袖、职业典范、火药桶、玻璃心、野心家、本地孩子、沉默寡言），性格带一个 `aura` 权重。队长由 `leadershipScore` 自动推举，综合能力、年龄、性格、出场数与士气，一旦产生就稳定下来，只有离队才会重选。

`roomState(s)` 把平均士气、性格总和、队长是否在位、张力值和不满人数合成一个 0–100 的气氛值，分为「拧成一股绳 / 平稳 / 暗流涌动 / 分裂 / 失控」五档。`roomEdge(s)` 把气氛折算成 ±2.4 的评分加成，直接进入 `matchPreview` 的 `adjustedRating`，也就是说气氛真的会改变预期进球，并在赛后「为什么是这个结果」的因果网格里单独占一格。

`roomShock(s, kind, player)` 是连锁反应的入口：卖人、解约、提拔青训、强推首发都会调用它。同一件事对不同性格的人后果不同——卖掉队长会让全队掉士气、袖标空缺、球迷风险上升；火药桶会在混合采访区甩话；本地孩子会提起自己小时候看谁踢球；野心家反而因为前面的人走了而高兴。

### 2. 宿敌与德比

开局固定一个同城宿敌（北港海星，老板秦百川，与既有 NPC 对应），带一个 0–100 的仇恨值。对阵宿敌时 `matchImportance` 返回「同城德比」，赛前会议多一个「德比喊话：叫板」选项，看台氛围（球迷值）在德比里被放大成 ±1.6 的评分加成——想赢德比，平时就得养球迷。

`settleDerby` 负责德比专属结算：赢球球迷 +5、董事会 +2 并写进队史；输球球迷 -5、董事会 -2、球迷风险上升；叫板过的话，赢输的幅度都翻一倍。仇恨值高到一定程度后 `rivalPulse` 会让宿敌主动出手：转会窗内对你身价最高的球员报价、抢先签走你盯上的市场目标，或者在采访里补一句话。

### 3. 四条人物故事弧

四位招牌人物各有一条四幕主线，按月推进，每月最多推进一幕，剧情卡优先于随机事件出现：

| 故事线 | 人物 | 四幕大致节奏 |
|---|---|---|
| 老队长的最后一季 | 当前队长（动态绑定） | 续约谈判 → 训练场冲突 → 一份来自升班马的邀请 → 告别赛或演播室 |
| 十七岁的第一件球衣 | 潜力最高的青训球员 | 是否提前提拔 → 豪门报价 → 伤病抉择 → 成名或流失 |
| 秦百川与那座城市 | 宿敌老板 | 互不挖角的酒局 → 德比前的头版 → 一个赌约 → 三年交锋的清算 |
| 那篇没发出去的稿子 | 记者程雨薇 | 泄露的工资表 → 定义你公众人设的专访 → 佣金调查或对手的黑料 → 年度人物 |

每一幕的选择写进该条线的 `flags`，后面的幕会读它——第一幕怎么对队长，第三幕他会不会自己选择留下；压过稿的人，第三幕会被查到佣金。第四幕根据累计选择给出不同收尾，写入队史里程碑，并在三年结算页的「三年的回响」里再出现一次。

### 4. 赛季末决战直播

最后一轮不再只是一份月报。`buildFinalDay` 在开赛前抓一份积分榜快照，判断你处在争冠日、保级日还是收官日，然后 `showFinalDay` 逐条推送：先讲清形势，再一场一场播报关键对手的比分，最后才是你自己的比赛和定格名次。每条消息一次点击，带频道感。

## 四、平衡说明

- 更衣室加成中位数接近 0（平均士气 60、性格总和 0 时约 -0.2 评分），是放大器而不是新的强度来源。
- 德比加成取决于球迷值而不是仇恨值，避免「被讨厌反而变强」的反直觉。
- 放置流存活基线未变（机器人回归：平均 22.3 个月，与改动前一致），开局破产曲线没有被动过。

## 五、UI / 美术审计

### 审计台怎么用

```bash
node tests/ui-audit/capture-screens.mjs   # 用假 DOM 真跑一局，抓 60+ 个界面的真实 HTML
node tests/ui-audit/build-audit.mjs       # 生成 ui-audit.html
open ui-audit.html                        # 每个画面同时按桌面 1000px 和手机 390px 渲染
```

审计页顶部是自动测量结果，页面里红框标出溢出、黄框标出被截断或被挤压的元素。检测规则：

横向溢出（`scrollWidth > clientWidth` 且祖先不可横滚）、文字截断（带 `text-overflow:ellipsis` 且已溢出）、弹窗超高（`scrollHeight > 90vh`，决策弹窗与报告弹窗分开计）、确认键够不到（最后一个按钮跑出弹窗且没有可滚动祖先）、按钮区需要滚动、窄列堆叠（用 Range 数文字行盒，避免把 grid 拉伸的子项误判）、卡片被压成细长条。

### 这一轮查出并修掉的问题

**终局直播借用了比赛时间轴的版式。** `.live-event` 的第一列固定 38px，是给「45′」这种分钟标记用的；终局直播往里塞的是「北港海星 3-1 岭南先锋」，被压成一条竖排。改成专用的 `.final-line`：标题独占一行，当前这条带绿色左边条和高亮背景，读起来像滚动战报。

**三年结算页的「回响」塞进了横向奖杯架。** `.honour` 最小宽度 126px，而弧线收尾文案是整句话，四张卡被压成细长条并出现横向滚动。改用 `.timeline`，标题加正文竖排。

**总览的故事线卡片太窄。** 加 `.honour.story`（最小宽度 196px、独立配色），标题不再折三行。

**赛前会议弹窗被挤到看不见确认键。** 原来最多 12 个按钮（3 基调 + 3 加码 + 4 青训 + 确认），桌面 932px、手机 983px，远超 90vh。三步压到 7 个：发布会三选一合成一个循环按钮（德比时自动多出「叫板」）、强推青训合成一个循环按钮、教学说明只在前两个月出现。同时把弹窗改成 flex 纵向布局——标题固定、正文自己滚、按钮区永远在屏幕内，报告类弹窗也一并受益（比赛中心从整窗滚动变成正文区滚动）。

**其他：** 手机上因果网格恢复两列（比赛中心从 1145px 降到约 900px）、三年蓝图从四列网格改成三列（不再空一格）、手机上弹窗按钮内边距收紧。

### 最终结果

42 个画面（21 个界面 × 桌面/手机），横向溢出 0、文字截断 0、窄列堆叠 0、确认键够不到 0。唯一剩下的是三年结算页在 390×700 手机上高 652px，比 90vh 多 22px——结算页本来就是整卡滚动，保留。
